# aisight 도움말 — 콘텐츠/디자인 분리 구조

이 사이트는 **글(콘텐츠)**과 **디자인(레이아웃·스타일)**이 완전히 분리되어 있습니다.

```
content/    ← 글만 있는 폴더 (마크다운). 텍스트만 고치고 싶다면 여기만 건드리면 됩니다.
design/     ← 디자인 폴더 (CSS, 페이지 틀, 다이어그램, 로고). 개발자가 다룹니다.
build.js    ← content + design을 합쳐서 실제 웹페이지(html)를 만들어주는 프로그램
_serve.js   ← 만들어진 사이트를 내 컴퓨터에서 미리 볼 수 있게 해주는 프로그램
index.html, a/*.html, o/*.html, c/*.html, assets/   ← build.js가 "자동으로 생성"하는 결과물.
                                                       직접 손대지 마세요 (다음 build 때 덮어써집니다).
```

## 글만 고치고 싶을 때

1. `content/` 폴더에서 고치고 싶은 페이지의 `.md` 파일을 찾아 엽니다 (메모장으로도 됩니다).
   - 예: "왜 지금 aisight인가" 페이지 → `content/a/challenge.md`
   - 폴더 구조가 곧 사이트 메뉴 구조와 같습니다. `content/a/products/agent.md`는
     `도입 검토 > aisight의 구성 > aisight Agent` 페이지입니다.
   - 하위 페이지를 가진 페이지는 `_index.md`라는 이름으로 저장됩니다
     (예: `content/a/_index.md` = "도입 검토" 섹션 첫 페이지).
2. 텍스트를 원하는 대로 고칩니다. (아래 "글쓰기 규칙" 참고)
3. 터미널에서 아래 명령 실행:
   ```bash
   node build.js
   ```
4. 결과 확인:
   ```bash
   node _serve.js
   ```
   그다음 브라우저에서 `http://localhost:4173` 접속.
5. 문제없으면 평소처럼 `git add -A && git commit -m "..." && git push` 로 배포합니다.

**개발 지식이 없어도 됩니다.** `.md` 파일 안에는 HTML 태그나 CSS 클래스 이름이 전혀 없습니다 —
전부 눈에 보이는 그대로의 글과, 아래 표에 있는 몇 가지 표시(`:::` 로 시작하는 줄)뿐입니다.

## 파일 맨 위 — 프런트매터

모든 `.md` 파일은 `---`로 둘러싸인 부분(프런트매터)에서 시작합니다.

```yaml
---
title: 왜 지금 aisight인가          # 페이지 제목 (필수)
summary: AI 도입이 PoC에서 멈추는 이유  # 목차 카드에 쓰이는 한 줄 요약 (선택)
intro: 기업의 AI 도입 시도는...       # 제목 바로 아래 나오는 굵은 리드 문단 (선택)
order: 10                          # 형제 페이지들 사이의 순서. 숫자가 작을수록 위 (선택, 기본 0)
---
```

- 최상위 3개 섹션(`content/a/_index.md`, `content/o/_index.md`, `content/c/_index.md`)에만
  `pill`, `pillClass`(`a`/`b`/`c` 중 하나)가 추가로 있습니다 — 홈 화면 카드의 색상 태그용입니다.
  이 값들은 그대로 두세요.
- `order`를 바꾸면 사이드바 메뉴 순서와 "이전/다음" 이동 순서가 함께 바뀝니다.
  같은 폴더 안 형제 파일들끼리 10, 20, 30 처럼 간격을 두면 나중에 사이 끼워넣기 편합니다.

## 글쓰기 규칙 (일반 텍스트)

일반 문단, 목록, 표, 소제목은 평범한 마크다운입니다.

| 하고 싶은 것 | 쓰는 법 |
|---|---|
| 굵게 | `**이렇게**` |
| 기울임 | `*이렇게*` |
| 코드체 | `` `pnpm install` `` |
| 링크 | `[표시할 글자](https://주소)` |
| 소제목 | 줄 맨 앞에 `### 소제목` |
| 목록 | 줄 맨 앞에 `- 항목` |
| 표 | `\| 헤더1 \| 헤더2 \|` 다음 줄에 `\| --- \| --- \|`, 그다음 데이터 행 |
| 표 안에서 작은 라벨(예: "요약") | 표 바로 위에 `##### 요약` |
| 문단 안에서 줄바꿈 | 줄 끝에 스페이스 두 칸 남기고 다음 줄 |

## 특수 블록 (`:::`으로 시작하는 부분)

문단만으로 표현하기 어려운 디자인 요소(카드, 강조 박스, 타임라인 등)는
`::: 이름` 으로 시작해서 `:::` 으로 끝나는 블록으로 씁니다. **디자인은 이 안에서 건드릴 게 없고,
안에 있는 글만 고치면 그대로 카드/박스 모양으로 나옵니다.**

### 강조 박스 (`callout`)
```
::: callout
label: 첫 응답은 느릴 수 있습니다
로컬 LLM 기준 첫 응답까지 30~60초가 걸릴 수 있습니다.
:::
```
경고성 박스는 `::: callout warn` 으로 씁니다.

### 카드 여러 개 (`cards`)
```
::: cards
#### 카드 제목 1
카드 1 설명

#### 카드 제목 2
카드 2 설명
:::
```
카드 개수에 따라 2단/3단 배치는 자동으로 결정됩니다.

### 자주 묻는 질문 (`faq`)
```
::: faq
#### 질문 1?
답변 1

#### 질문 2?
답변 2
:::
```
클릭하면 펼쳐지는 아코디언 형태로 나옵니다.

### 통계 숫자 (`stats`)
```
::: stats
3.8배 | 매출 성장 — 20억(2022) → 93억(2025)
70%+ | 주요 고객 장기 계약 매출 비중
:::
```
`숫자/화살표 | 설명` 형식, 한 줄에 하나씩.

### 타임라인 (`timeline`)
```
::: timeline
1개월 | 진단과 기획
데이터 환경과 업무를 함께 살펴봅니다.
- 체크리스트 항목 1
- 체크리스트 항목 2
산출물: 진단 리포트

2~3개월 | POC 검증
...
:::
```
각 단계는 빈 줄로 구분합니다. `- ` 목록과 `산출물:` 줄은 선택 사항입니다.

### 다이어그램 (`diagram`)
```
::: diagram products
aria: 화면낭독기용 설명 문구
caption: 그림 아래 작게 나오는 캡션
:::
```
`products`/`flow`/`excel`/`desktop` 중 하나만 쓸 수 있습니다 (그림 자체는 `design/diagrams/`에
있는 완성된 그림이고, 새 그림을 추가하려면 개발자가 SVG 파일을 만들어야 합니다).

## 새 페이지 만들기 / 순서 바꾸기 / 페이지 없애기

- **새 페이지 추가**: 같은 폴더에 `.md` 파일을 새로 만들고 프런트매터(`title`, `order` 등)만
  채우면, `node build.js` 실행 시 사이드바와 이전/다음 이동에 자동으로 나타납니다.
- **순서 바꾸기**: 프런트매터의 `order` 숫자만 바꾸면 됩니다.
- **페이지 삭제**: `.md` 파일을 지우고 `node build.js`를 다시 실행하면 됩니다. 다만 예전에
  생성됐던 `.html` 결과 파일은 자동으로 지워지지 않으니, 필요하면 같은 이름의 `.html` 파일을
  수동으로 삭제해 주세요.

## 디자인을 고치고 싶을 때 (개발자용)

`design/` 폴더만 건드리면 되고, `content/`의 어떤 `.md` 파일도 건드릴 필요가 없습니다.

- `design/style.css` — 색상, 여백, 글꼴 등 모든 스타일
- `design/template.html` — 사이드바·헤더·푸터 등 모든 페이지가 공유하는 틀 (`{{...}}` 자리에
  build.js가 실제 내용을 채워 넣습니다)
- `design/nav.js` — 모바일 메뉴 토글, 검색창 필터링 스크립트
- `design/diagrams/*.svg` — 4개의 손그림 다이어그램 원본
- `design/images/about-hero-logo.png` — 세일링스톤 로고

고친 뒤에는 `node build.js`로 다시 생성하면 모든 페이지에 반영됩니다.
